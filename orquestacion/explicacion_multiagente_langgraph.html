Multiagente con LangGraph: cómo funciona

Un solo LLM contesta una vez con lo que sabe. LangGraph permite algo distinto: modelar la conversación como un grafo de estados, donde un supervisor deriva cada pregunta a un agente especializado. Esta explicación usa el grafo real que ya corre en este repo.

decisión / ruteo ejecución de un agente fin del grafo estado compartido

El problema

¿Por qué no un solo agente que haga todo?

Se puede meter todo en un único system prompt: "resolvé cálculos, traducí textos y explicá conceptos". Funciona hasta que el prompt crece, las instrucciones de una tarea contaminan a las otras, y no hay forma de darle a la parte matemática una herramienta propia sin que el resto del prompt se vuelva ruido. La alternativa es partir el problema: varios agentes chicos y enfocados, más un supervisor liviano que solo decide a quién le toca.

El modelo

Un grafo de estados: nodos, aristas y estado

LangGraph modela la orquestación con tres piezas. Un nodo es una función de Python que recibe el estado actual y devuelve los campos que quiere actualizar. Una arista conecta un nodo con el siguiente; puede ser fija o condicional (una función decide, en tiempo de ejecución, a qué nodo ir). Y el estado es un diccionario compartido —en este caso un TypedDict llamado Estado, con pregunta, ruta y respuesta— que todos los nodos leen y van completando a medida que el grafo avanza.

El dato que viaja

El estado se va completando en cada nodo

Nada se pasa "por parámetro" de un nodo a otro: todos comparten el mismo diccionario de estado. Cada nodo recibe la versión actual, hace su trabajo, y devuelve solo los campos que modifica; LangGraph mezcla ese resultado con el estado existente antes de pasarlo al siguiente nodo.

Trazado real

Una corrida paso a paso

Con la pregunta "Cuanto es 12 * (3 + 4)?", así se mueve la ejecución sobre el grafo (ver orquestacion/multiagente_langgraph.py):

  1. invoke()

    app.invoke({"pregunta": ..., "ruta": "", "respuesta": ""}) entra por START y pasa al primer nodo del grafo: supervisor.

  2. supervisor() clasifica

    Le pide al LLM que devuelva una sola palabra clave. La respuesta se busca dentro de RUTAS_VALIDAS con parseo tolerante; para esta pregunta da "matematico", que se guarda en estado["ruta"].

  3. arista condicional

    add_conditional_edges("supervisor", _elegir_ruta, {...}) llama a _elegir_ruta(estado), que simplemente devuelve estado["ruta"]. LangGraph usa ese valor como nombre del próximo nodo: matematico.

  4. matematico() ejecuta

    Primero intenta _eval_seguro("12 * (3 + 4)"), una evaluación aritmética sandboxeada (sin acceso a builtins). Da 84, así que ni siquiera vuelve a llamar al LLM — el nodo devuelve la respuesta directo.

  5. arista fija → END

    add_edge("matematico", END) cierra el grafo. El estado final —con pregunta, ruta y respuesta completos— es lo que devuelve invoke().

Dato del código: si la pregunta no tiene una expresión aritmética clara (por ejemplo, "quién inventó la suma"), _eval_seguro devuelve None y el nodo matematico cae a un segundo LLM.invoke() con un prompt distinto ("resolvé paso a paso"). Cada agente puede tener su propia mezcla de herramienta + modelo, sin afectar a los demás nodos.

Referencia

Piezas del API que arman el grafo

PiezaQué hace
StateGraph(Estado)Crea el grafo, tipado con el TypedDict que define la forma del estado compartido.
add_node(nombre, fn)Registra una función como nodo; recibe el estado y devuelve un dict con los campos que actualiza.
add_edge(a, b)Arista fija: al terminar el nodo a, siempre sigue b. START y END son marcadores especiales de entrada y salida.
add_conditional_edges(a, fn, mapa)Arista dinámica: tras a, se llama a fn(estado); el string que devuelve se busca en mapa para elegir el próximo nodo.
.compile()Valida el grafo y lo convierte en algo ejecutable (una app).
.invoke(estado_inicial)Corre el grafo de punta a punta desde START hasta END y devuelve el estado final.

Más allá de este ejemplo

Cómo se extiende el patrón

Este grafo hace un solo salto: supervisor → agente → END. Es el caso más simple para que se entienda el mecanismo, pero el mismo modelo —nodos, aristas, estado compartido— escala a flujos más largos:

Agentes que se llaman entre sí: un agente puede terminar en otro nodo en vez de END, por ejemplo para pasarle el resultado a un segundo especialista.

Nodo revisor: un nodo extra que valida la respuesta y, si no alcanza, usa una arista condicional para volver a mandar el estado al mismo agente o a otro.

Memoria / checkpoints: LangGraph puede persistir el estado entre llamadas (checkpointer), para que una conversación multi-turno recuerde rutas y respuestas anteriores sin volver a empezar del START.

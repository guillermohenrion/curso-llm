Generador-Crítico: el grafo que se corrige a sí mismo

Los dos ejemplos anteriores de LangGraph corrían en un solo salto: supervisor → agente → END. Este grafo agrega algo nuevo — un ciclo: un agente escribe, otro lo critica, y si no alcanza, vuelve a escribir. Esta explicación usa el grafo real de este repo.

decisión del crítico ejecución (generar / reescribir) fin del grafo estado compartido

El problema

¿Por qué no quedarse con la primera respuesta?

Un LLM sin revisión escribe una vez y eso es lo que hay: si la respuesta es genérica o le falta algo, nadie se dio cuenta. El patrón generador-crítico (también llamado reflexión) agrega un segundo agente cuyo único trabajo es leer el resultado con ojo crítico y, si no convence, decirle al primero qué mejorar — no solo "está mal".

El grafo

generador → crítico → (revisar | fin)

Dos nodos, tres aristas: START → generador y generador → critico son fijas. La tercera es condicional y es la que cierra el ciclo: según lo que decida _siguiente_paso(estado), vuelve a generador (con la crítica como feedback) o corta a END. El corte pasa por dos motivos distintos: el crítico aprobó, o ya se gastaron los MAX_INTENTOS — un salvavidas para que el grafo no gire para siempre si el crítico nunca queda conforme.

El dato que viaja

El estado acumula intentos, no solo campos

Igual que en el supervisor, todo vive en un TypedDict Estado compartido (tarea, borrador, criticas, intentos, aprobado). La diferencia es que acá el mismo campo se pisa varias veces: cada vuelta por generador reemplaza borrador usando el criticas que dejó la vuelta anterior.

Trazado real

Una corrida completa, de punta a punta

Pedido: "Explica en una sola oracion que es una API REST". Esta es la salida real de python generador_critico_langgraph.py (sin editar):

  1. generador — intento 1

    Sin criticas previas, arma el prompt solo con la tarea y escribe el primer borrador.

  2. critico — rechaza

    _siguiente_paso devuelve "revisar" (no aprobó y quedan intentos), así que la arista condicional vuelve a generador.

    "La explicación es correcta y completa, pero podría ser más concisa."
  3. generador — intento 2

    Esta vez estado["criticas"] no está vacío: el prompt cambia a modo "reescribí con este feedback" y usa el borrador anterior + la crítica como input.

  4. critico — rechaza otra vez

    Sigue sin convencer del todo. Como intentos == 2 < MAX_INTENTOS (3), todavía hay margen: vuelve a generador una vez más.

    "La explicación es correcta pero podría ser más concisa."
  5. generador — intento 3

    Reescribe de nuevo con la última crítica.

  6. critico — aprueba → END

    aprobado=True, así que _siguiente_paso devuelve "fin" sin importar cuántos intentos queden. El grafo corta y devuelve el estado final.

    "La explicación es correcta y completa, sin necesidad de modificaciones."

Resultado final (estado_final["borrador"], 3 intentos, aprobado=True):

"Una API REST es un conjunto de estándares que permite a las aplicaciones comunicarse a través de recursos utilizando métodos como GET, POST, PUT y DELETE, facilitando la interacción y el intercambio de datos."

Cuando el crítico nunca afloja: con pedidos más subjetivos (un eslogan, una bio graciosa), en la práctica el crítico de este modelo (gemma3) puede rechazar las 3 veces sin aprobar nunca. Ahí es donde entra el salvavidas: al llegar a MAX_INTENTOS, _siguiente_paso devuelve "fin" igual, y el grafo entrega el último borrador con aprobado=False en vez de girar para siempre.

Referencia

Qué cambia respecto al grafo del supervisor

PiezaQué hace acá
add_conditional_edges("critico", ...)El mapa incluye "revisar": "generador" — apunta a un nodo anterior, no solo hacia adelante. Eso es lo que crea el ciclo.
MAX_INTENTOSSalvavidas propio del código: corta el ciclo aunque el crítico jamás apruebe. Sin esto, un crítico demasiado exigente lo haría girar indefinidamente.
límite de recursión de LangGraphAdemás del salvavidas propio, LangGraph corta cualquier grafo que pase de 25 pasos (recursion_limit) — una segunda red de seguridad si el conteo propio fallara.
estado["criticas"]Hace doble función: si está vacío, generador escribe desde cero; si tiene texto, reescribe usándolo como feedback puntual.
